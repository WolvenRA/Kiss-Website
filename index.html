Overview

What is Kiss?

Kiss is a designed-from-scratch computer system. Not a modification of x86. Not a RISC-V variant. A clean-sheet architecture informed by 70 years of computing lessons — taking the best ideas from the IBM AS/400, seL4, and combining them with original design decisions that prioritize correctness, clarity, and real-world utility.

This is not an academic exercise. Kiss was designed with the goal of creating a system from the human perspective rather than being optimized for the silicon. While performance still matters, the primary design goals are ease of understanding, natural (1 based indexing, decimal math) ease of programming and low level abilities with high level functionality.

3 Data Types

Three native data types — Binary (unsigned), Integer (ones complement), and Decimal (packed 5-bit digits) — each with dedicated ALU hardware. No floating-point rounding surprises. Numbers work the way humans expect them to.

Architecture

Key differentiators that set Kiss apart

Decimal Arithmetic

Native decimal type with packed 5-bit digits and embedded decimal point. No floating-point rounding errors. Three dedicated ALUs — decimal, integer, and binary — each optimized for its type.

100-Bit Instructions

Every instruction is exactly 100 bits: 5 Conditional Execution Bits + 12 opcode + 8 Command Modifier Bits + 5×15-bit operands. Clean, consistent, no variable-length decoding. The decoder is simple because the format is simple.

Ones Complement, Sign Bit 1 = Positive

Knuth's insight applied: a subtractor ALU instead of an adder ALU eliminates virtually all negative zero results. Using 1 as the poitive sign bit gives monotonic ordering and allows universal unsigned compare. Integers and decimals sort naturally without type-specific comparison logic.

5-Way SMT, In-Order Execution

Threads hide memory latency instead of out-of-order speculation. Reclaimed silicon budget goes to ALUs, registers, and caches — where it actually matters. Simpler, more predictable, more efficient.

Dedicated Kernel Core

Application cores never enter kernel mode. No mode switches, no KPTI patches, no interrupt preemption on app cores. Syscalls go through lightweight message passing to the kernel core. Security by architecture, not by afterthought.

One-Based Everything

All indexing starts at 1. Zero is always an error sentinel — an uninitialized pointer, an invalid index, a missing value. No more off-by-one bugs from counting conventions that fight human intuition.

The Toolchain

Assembler, linker, and execution engine

Assembler — kasm

Lexer → Parser → Preprocessor → Encoder → Emitter

  • 590 mnemonics across 33 instruction families
  • Macros and conditional assembly (AsmIf)
  • File inclusion directives
  • Typed literals: #B:, #I:, #D:, #A:
  • Data directives: Def Bin/Int/Dec/Bit/Txt/Sym

Linker — kiss-link

  • Separate compilation with Export/Import
  • Relocatable .kobj object files
  • Symbol resolution and address patching
  • Multi-module program assembly

Execution Engine

  • Full register model: 5 banks × 2000 bits
  • 10 data stacks per thread
  • CEB conditional execution bits
  • Instruction-level simulation and tracing

Get started with Kiss

Kiss-100 and Kiss-50 Targets

Kiss-100 is the full-width architecture target: 100-bit instructions, 50-bit addressing, five general-purpose register banks, and ten data stacks. Kiss-50 is the compact target: 50-bit instructions, 30-bit addressing, one or two register banks, one data stack, and three compact operand slots. The assembler language is intentionally shared where possible; Kiss-50 documentation focuses on the structural and encoding differences.

Kiss-50 Downloads and Reference

If you are starting with Kiss-50, read the Kiss-50 differences guide first, then install K5VM. The guide explains the compact register layout, reduced operand model, CMB differences, and literal/materialization strategy without duplicating the full ISA and assembler manuals. A dedicated Kiss-50 VS Code extension is available for .k5asm files.
